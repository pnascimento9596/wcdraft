# Basis-aware offer tiering — 2026-07-18

## Outcome

Basis-aware offer tiering is implemented against pinned base
`735e0ecc127ac13b90527141b5fb43c019f0b03e`. Career behavior is byte-identical; Current offers
now use the Current display overall that the player sees. The runtime schema, rating values,
draft-pool and scenario bytes, tier/spread/floor/scorer algorithms, simulation, scoring, best-XI,
and leaderboard season are unchanged. The engine boundary is
`engine-2026.07.18-basis-aware-tiering`.

The ratified contract is:

> Offer tiering operates on the display value of the **selected rating basis**. ENG-08 is
> unchanged: display values are permitted for offer tiering ONLY — never scoring, sim, or
> best-XI. Basis-aware tiering is an application of ENG-08, not an amendment to it.

## Implementation shape and tradeoff

Architect-delegated decision: use a zero-schema, core-side dual-value seam. The compact bundle
does not contain `choice_overall`; it already contains Career at `ratings[].overall` and Current at
`ratings[].basis_ratings.current.overall`. Browser, server, test, and measurement materializers now
place those two values into `DraftPlayerCard.choice_overall`, and the single exported
`resolveChoiceOverall(card, ratingBasis)` selects the configured basis inside `packages/core`.
This avoids duplicating derived fields and avoids a runtime schema bump. The tradeoff is a widened
core-only input shape; legacy scalar compatibility is deliberately Career-only, while a scalar in
a Current run resolves honestly to `null` rather than borrowing Career.

All live creation, token reconstruction, and the analyzer call the same core draft transitions.
The analyzer does not reproduce tiering logic.

## Consumer adjudication

| Consumer                                                | Decision                                                                                                                                                                 |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Classic/Memory choose-from-3 ranking and tier buckets   | Resolve `choice_overall` under the selected basis. Spread, eight buckets, retained tiers 0/1/2, and softened U5 floor are unchanged.                                     |
| Diversity scorer `choice_overall / 1000` term           | Resolve the same selected-basis value through the same seam. Its coefficient and algorithm are unchanged.                                                                |
| Open Draft representative card and visible rating order | Select and order each player's representative card under the configured basis. This prevents a Career representative from standing in for a Current offer.               |
| Blind Open representative card                          | Select the representative under the configured basis before the unchanged blinded position/card-ID order. Masking remains downstream and does not affect offer identity. |
| Memory rendering                                        | Leave `blindCardRatingView` untouched. Opacity is a rendering property; offer construction uses the selected basis before masking.                                       |
| RARE/draw probability                                   | No `choice_overall` read exists; unchanged.                                                                                                                              |
| Fit teaching and offer UI                               | They do not independently construct the tier input; selected-basis display rendering remains separate.                                                                   |
| Sim, scoring, team strength, best-XI                    | No display-value read is allowed or added; ENG-08 guard remains green for both bases.                                                                                    |

## Token and replay boundary

`t3` records choice indices and `t4` records explicit player/manager card IDs. Both carry
`rating_basis` plus the six-anchor conjunction `sv/dv/rv/ev/uv/hv`; both reconstruct through the
same core create/target/pick transitions as live drafts. The engine bump therefore fences old
tokens before reconstruction.

`DIFFERENT_BUILD` without re-derived score/lineup data. Fresh t3 and t4 tests round-trip Career and
